Why this exists

Six governance pain points

DAM is Indonesia's sovereign-wealth governance gatekeeper. Today's operating model is manual, fragmented, and exposes individual officers to personal liability.

A · Multiple versions of truth

Parallel drafting → mismatched artefacts. ~30% of senior time on manual reconciliation.

B · Over-documentation

80% of NOTA content is descriptive restatement produced as a defensive liability shield.

C · Unclear SOP routing

Judgment-based pathway selection → under-routing (missed approvals) and over-routing (delays).

D · Repetitive drafting

Same structure, same logic, same data pulled from submissions, over and over.

E · Uncontrolled AI

Public AI tools on ungoverned cloud storage → hallucination, leakage, no auditability.

F · Personal liability

Officers bear individual accountability. More involvement = more exposure. Codify low-risk rules.

System design

Clean-architecture, ports & adapters

Dependencies point inward. The domain core is framework-free; every external dependency — model, database, storage, audit — sits behind a port. Swapping a provider or cloud is an adapter change, never a rework.

Non-negotiable guardrails

How liability is engineered out

Rules decide, AI explains

SOP selection, approval thresholds, and risk tiers are evaluated by a deterministic YAML rulebook. The model only phrases the explanation — it never makes a governance decision. Every fired rule id is logged.

Grounding is a hard gate

An unsourced sentence is suppressed, not warned about — replaced with "Low confidence — manual input required". 100% source traceability, validated at generation time, on every model in the mix.

Humans keep the judgment

NOTA sections split into descriptive (AI, ~80%) and judgment (always human, ~20%). A contamination scan blocks any AI text in a judgment section as a Severity-1 incident.

Everything is attributable

Append-only audit of every model call, rule firing, and sign-off — with role, model, version, and the authenticated identity. 7-year tamper-evident retention. Any output → full provenance in ≤2 clicks.

LLM foundation

Two-tier model mix, routed by task role

A managed online-API tier (Claude) and a self-host tier (vLLM, OpenAI-compatible) for every role. Policy-driven routing: outage fallback, classification-forced tier, and an edge profile that pins everything local.

Proof of concept

Eight capability modules

The Phase 1 feature set. Status reflects the working scaffold after Sprint 1 — green where the slice runs end-to-end today, in-progress where it matures to full PRD spec in the named sprint.

FR-1 · P1

AI-assisted drafting engine

First-draft descriptive NOTA sections from submissions, templates, and historical notes via RAG. Judgment sections left blank for the reviewer. Every paragraph cites its source.

In progress → S3Critical<5 min draft
FR-2 · P1

Cross-document consistency checker

Compares NOTA vs board note vs decision vs communication against the master. Eight inconsistency types, Critical/Warning/Informational severity, with quoted excerpt pairs and resolutions.

In progress → S3Critical≥90% precision
FR-3 · P1

Version control & single source of truth

Master-document hierarchy with version history, checkout/check-in locking, diff view, post-queue immutability, and automatic propagation flags to dependent artefacts.

In progress → S3Critical
FR-4 · P1

Rule-based eligibility & SOP routing

Evaluates a request against delegation-of-authority thresholds and governance rules: which SOP, what approvals, pre-conditions, timeline. Ambiguity routes to a human resolver.

Scaffold ✓ → S4Critical<30 s
FR-5 · P1

Secure enterprise AI sandbox

All inference inside the DAM boundary, no external transmission or training. Single audited model entry, RBAC, data classification gating model tiers, complete AI interaction log.

In progress → S6Critical
FR-6 · P1

Integrated workflow orchestration

Submission intake → eligibility → drafting → review → board → decision → communication. System-driven progression with risk-tier checkpoints and SLA bottleneck alerts.

Scaffold ✓ → S4Critical
FR-7 · P2

SOP digitization & decision routing

SOPs as versioned, approval-gated decision trees with escalation paths. Non-technical visualization for compliance officers. Coverage dashboard tracks migration.

In progress → S4High
FR-8 · P2

Risk-based automation segmentation

Multi-dimensional risk scoring (value, entity risk, novelty, precedent, regulatory exposure). Low-risk runs fully automated; complex routes to human-in-the-loop. Auto-escalation on errors.

Scaffold ✓ → S4High
FR-9 · P3 · Phase 2

BPI-wide governance platform

Multi-tenant extension across DAM, DIM, DSI with shared artefact templates, workflow definitions, and SOP libraries under central BPI governance.
